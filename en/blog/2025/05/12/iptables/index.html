iptables​

参考: iptables详解

数据走向流程:

prerouting->是否为本机->input->output
               |                |
               否               |
               |                |
             forward-------->postrouting

走向图:

四张表​

  • filter表:负责过滤功能,防火墙；内核模块: iptables_filter

  • nat表: network address translation,网络地址转换功能；内核模块:iptable_nat

  • mangle表: 拆解报文,做出修改,并重新封装的功能；iptable_mangle

  • raw表:关闭nat表上启用的连接追踪机制；iptable_raw

默认定义的链需要把自定义链当做动作去引用. 取反操作与同时指定多个IP的操作不能同时使用. 当一条规则中有多个匹配条件时,这多个匹配条件之间,默认存在与的关系

处理动作​

  • ACCEPT:允许数据包通过.
  • DROP:直接丢弃数据包,不给任何回应信息,这时候客户端会感觉自己的请求泥牛入海了,过了超时时间才会有反应.
  • REJECT:拒绝数据包通过,必要时会给数据发送端一个响应的信息,客户端刚请求就会收到拒绝的信息.
  • SNAT:源地址转换,解决内网用户用同一个公网地址上网的问题.
  • MASQUERADE:是SNAT的一种特殊形式,适用于动态的、临时会变的ip上.
  • DNAT:目标地址转换.
  • REDIRECT:在本机做端口映射.
  • LOG:在/var/log/messages文件中记录日志信息,然后将数据包传递给下一条规则,也就是说除了记录以外不对数据包做任何其他操作,仍然让下一条规则去匹配.

链的规则存放于哪些表中(从链到表的对应关系)​

  • PREROUTING的规则可以存在于: raw表、mangle表、nat表.
  • INPUT的规则可以存在于: mangle表、filter表,(centos7中还有nat表,centos6中没有).
  • FORWARD的规则可以存在于: mangle表、filter表.
  • OUTPUT的规则可以存在于: raw表、mangle表、nat表、filter表.
  • POSTROUTING的规则可以存在于: mangle表、nat表.

表中的规则可以被哪些链使用(从表到链的对应关系):​

  • raw表: PREROUTING、OUTPUT
  • mangle表: PREROUTING、INPUT、FORWARD、OUTPUT、POSTROUTING
  • nat表: PREROUTING、OUTPUT、POSTROUTING(centos7中还有INPUT,centos6中没有)
  • filter表: INPUT、FORWARD、OUTPUT

下图中nat表在centos7中的情况就不再标明:

之所以出现上图中的情况,是因为IPTABLES的工作机制导致的,上例其实是利用了这些机制,完成了所谓的白名单机制,并不是我们所描述的黑名单机制(INPUT链中的那些多出来的ACCEPT规则)

保存临时规则(默认存到/etc/sysconfig/iptables): service iptables save

导入规则: iptables-restore < ${IPTABLES_CONFIG}

-i只用于PREROUTING链、INPUT链、FORWARD链.
-o只用于FORWARD链、OUTPUT链、POSTROUTING链.

用扩展模块的时指定筛选条件都得用--. 在没有指定模块的时候,iptables默认会使用与-p选项对应的协议名称相同的模块,所以-p tcp --dport 80是一种简写.

--dport22:25表示22到25之间的所有端口.

扩展模块功能介绍​

tcp模块​

--tcp-flags用于匹配tcp协议的标识位.

iptables -t filter -I INPUT -p tcp -m tcp --dport 22 --tcp-flags SYN,ACK,FIN,RST,URG,PSH SYN -j REJECT # tcp所有标识位中SYN必须为1,其余必须为0
iptables -t filter -I OUTPUT -p tcp -m tcp --sport 22 --tcp-flags SYN,ACK,FIN,RST,URG,PSH SYN,ACK -j REJECT # tcp所有标识位中SYN、ACL必须为1,其余必须为0
iptables -t filter -I INPUT -p tcp -m tcp --dport 22 --tcp-flags ALL SYN -j REJECT # 上面的简写
iptables -t filter -I OUTPUT -p tcp -m tcp --sport 22 --tcp-flags ALL SYN,ACK -j REJECT # 上面的简写
iptables -t filter -I INPUT -p tcp -m tcp --dport 22 --syn -j REJECT # 等于第一次握手:  --tcp-flags SYN,RST,ACK,FIN SYN

--tcp-flags的使用分为两个部分,第一部分表示需要匹配的标识位.第二部分表示需要为1的标识位,其它的标识位必须为0.

multiport模块​

解决了tcp模块不能处理多个不连续的端口设置问题,不过只能用于tcp、udp协议: -m multiport --dports 1,22,80

iprange模块​

解决了默认不能处理范围IP的情况:

  • -m iprange --src-range 192.168.1.127-192.168.1.146

  • -m iprange --dst-range 192.168.1.127-192.168.1.146

中间通过-号隔开,支持取反操作

string模块​

匹配报文字符串:

iptables -I INPUT -m string -algo bm --string "OOXX" -j REJECT

PS: 没用成功过模糊匹配

time模块​

时间段匹配报文,如果报文到达的时间在指定的时间范围以内,则符合匹配条件.

注意: time模块默认使用的时区是UTC,可以加上–kerneltz来使用本地时区.

iptables -t filter -I OUTPUT -p multiport --dports 80,443 -m time --timestart 09:00:00 --timestop 18:00:00 -j REJECT 拒绝早上9点到晚上6点的出口报文

其它选项: --weekdays 6,7、--monthdays 22,23

都支持取反.

connlimit模块​

  • iptables -I INPUT -p tcp --dport 22 -m connlimit --connlimit-above 2 -j REJECT 限制每个IP的链接数量上限为2

  • --connlimit-mask选项用来划分网段,不能单独使用.

  • iptables -I INPUT -p tcp --dport 22 -m connlimit --connlimit-above 20 --connlimit-mask 24 -j REJECT表示某C类网段中同时只能有20个tcp连接. 24代表掩码225.225.225.0.

    PS: 掩码计算规则

limit模块​

用于限流.

iptables -I INPUT -p icmp -m limit --limit 10/minute -j ACCEPT一分钟内最多流入10个包.

单位: second、minute、hour、day

--limit-burst选项是令牌桶的令牌分配选项,不能单独使用.

iptables -t filter -I INPUT -p icmp -m limit --limit-burst 3/second --limit 10/minute -j ACCEPT

state扩展​

icmp对应的扩展介绍(主要说了PING相关的配置)

在TCP/IP协议簇中,UDP和ICMP是没有所谓的连接的,但是对于state模块来说,tcp报文、udp报文、icmp报文都是有连接状态的,我们可以这样认为,对于state模块而言,只要两台机器在你来我往的通信,就算建立起了连接.

对于state模块的连接而言,连接其中的报文可以分为5种状态: NEW、ESTABLISHED、RELATED、INVALID、UNTRACKED.

  • NEW:连接中的第一个包,状态就是NEW,我们可以理解为新连接的第一个包的状态为NEW.
  • ESTABLISHED:我们可以把NEW状态包后面的包的状态理解为ESTABLISHED,表示连接已建立.
  • RELATED:从字面上理解RELATED译为关系. 在ftp中有数据连接和处理客户端命令传输的命令连接,其中的数据连接中的报文就可能存在RELATED状态,因为这些报文与命令连接中的报文有关系.
  • INVALID:如果一个包没有办法被识别,或者这个包没有任何状态,那么这个包的状态就是INVALID,我们可以主动屏蔽状态为INVALID的报文.
  • UNTRACKED:报文的状态为untracked时,表示报文未被追踪,当报文的状态为Untracked时通常表示无法找到相关的连接.

state模块就可以匹配这些连接状态.

iptables -I INPUT -s 118.178.189.230 -m state --state NEW -j REJECT拒绝指定IP的请求连接(典型的例子是ssh).

iptables -I INPUT -m state --state RELATED,ESTABLISHED -j ACCEPT
iptables -A INPUT -j REJECT

# 这样就实现了只能由当前主机向外发起连接以及后续通信,不允许其它网络主机向当前主机主动请求连接,避免`主动攻击问题`.

自定义链表​

创建步骤

iptables -N ${CHAIN_NAME}
iptables -I ${CHAIN_NAME} -s 192.168.3.188 -j REJECT # 和系统定义的链表一样的操作
iptables -I INPUT -p tcp --dport 80 -j ${CHAIN_NAME} # 自定义链表不能直接路由,必须通过系统定义的链表匹配后路由

-X选项可以删除自定义链,但需要满足两个条件:

  • 自定义链没有被任何默认链引用,即自定义链的引用计数为0.
  • 自定义链中没有任何规则,即自定义链为空.

删除步骤

iptables -D INPUT 1 # 删除依赖链中对应的记录
iptables -F ${CHAIN_NAME} # 清空自定义链中记录
iptables -X ${CHAIN_NAME} # 删除链

将iptables配置成网络防火墙

动作后面的选项​

ACCEPT、DROP、REJECT等动作都有一些常用选项.

  • REJECT

    • 可用参数:
      • --reject-with(作用是告诉客户端拒绝原因)
      • 语法: iptables xxxx -j REJECT --reject-with icmp-net-unreachable
      • 可选值: 
        icmp-net-unreachable 
        icmp-host-unreachable 
        icmp-port-unreachable  # 默认 
        icmp-proto-unreachable 
        icmp-net-prohibited 
        icmp-host-pro-hibited 
        icmp-admin-prohibited

LOG​

LOG动作只负责记录匹配到的报文的相关信息,不负责对报文的其他处理.

日志默认存放到/var/log/messages

自定义存放位置:

vim /etc/rsyslog.conf

# 追加
kern.warning /var/log/iptables.log

service rsyslog restart

选项:

  • --log-level 指定记录日志的日志级别,可用级别有：emerg、alert、crit、error、warning、notice、info、debug
  • --log-prefix 记录到的相关信息添加标签之类的信息,以便区分各种记录到的报文信息,方便在分析时进行过滤.

    iptables -I INPUT -p tcp --dport 80 -j LOG --log-prefix "tcp-80"

其它动作​

iptables动作总结之二

其它的SNAT、DNAT、MASQUERADE、REDIRECT懒得写了.

  • SNAT、DNAT: 就是IP、PORT做NAT路由转换.
  • MASQUERADE就是解决动态IP用SNAT配置路由表麻烦的问题,MASQUERADE里的IP地址会动态获取到当前主机的公网IP
  • REDIRECT是在本机上进行端口映射用的. 
    iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-ports 8080 # 将tcp协议中目标端口为80的请求改为8080

    REDIRECT规则只能定义在PREROUTING链或者OUTPUT链中.

注意: 因为这四个动作都是用来做路由转换的,所以是用nat表,而不是用默认的filter表.

写在最后​

几个最佳实践

  • 针对相同服务的规则,更严格的规则应该放在前面.
  • 当一条规则中有多个匹配条件时,条件之间默认存在与的关系.
  • 在不考虑1的情况下,应该将更容易被匹配到的规则放置在前面(效率).
  • 当IPTABLES所在主机作为网络防火墙时,在配置规则时,应着重考虑方向性,双向都要考虑,从外到内,从内到外.
  • 在配置IPTABLES白名单时,往往会将链的默认策略设置为ACCEPT,通过在链的最后设置REJECT规则实现白名单机制,而不是将链的默认策略设置为DROP,如果将链的默认策略设置为DROP,当链中的规则被清空时,管理员的请求也将会被DROP掉.
